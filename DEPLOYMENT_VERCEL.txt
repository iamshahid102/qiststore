================================================================================
QIST STORE — VERCEL DEPLOYMENT GUIDE
ONE PROJECT: Next.js storefront + Express API (Vercel Services)
================================================================================
Updated : 18 October 2026
Goal    : Ek hi Vercel project mein storefront (Next.js) aur API (Express) dono
          deploy hon, shared domain par, aur deployment ke baad koi route
          redirect / 404 / "API dead" issue na aaye.

Important: yeh guide "Vercel Services" use karti hai (1 project = 2 services).
           Purana "root api/index.ts function" wala setup hata diya gaya hai,
           kyunki Vercel monorepo mein framework detection Root Directory ke
           package.json se hoti hai — root par next nahi hai, is liye Next app
           static maan li jaati thi. Services isi problem ka official hal hai.

--------------------------------------------------------------------------------
1. ARCHITECTURE (kaise kaam karta hai)
--------------------------------------------------------------------------------
  vercel.json (repo root) do services declare karta hai:

    services:
      web  → root: client/   framework: nextjs    (storefront, SSR/ISR/static)
      api  → root: server/   framework: express   (wahi Express app, as-is)

    rewrites (top-level public routing, order matters):
      /health              → api service
      /api/v1/(.*)         → api service
      /(.*)                → web service        (catch-all, last)

  Vercel dono ko alag-alag build karta hai, lekin ek hi deployment + ek hi
  domain par serve karta hai. Service ko ORIGINAL path milta hai
  (/api/v1/products → api service ko bhi /api/v1/products hi milta hai),
  aur Express app pehle se /api/v1 par mounted hai — is liye server code mein
  koi path change nahi karna pada.

  Express service = ek Vercel Function (Fluid compute).
  Service entrypoint = `server/index.mjs` (root par, .mjs) — iska kaam sirf
  Express preset ko satisfy karna aur compiled server ko boot karna hai.
  ASLI server `server/src/index.ts` hai → `npm run build -w server` (tsc) se
  `server/dist/index.js` banta hai; service lambda ke files `dist/` se aate
  hain aur handler `index.js` hota hai. Isi liye:
     • root `src/app.ts` ko `src/create-app.ts` rename kiya gaya (warna Express
       preset `dist/app.js` ko entry maan kar bundle karta tha — jo sirf app
       factory hai, listen nahi karta),
     • `server/scripts/write-dist-manifest.mjs` build ke baad
       `dist/package.json = {"type":"module"}` likhta hai, warna lambda root par
       package.json na hone se Node `dist/*.js` ko CommonJS samajh kar
       "Cannot use import statement outside a module" par crash kar deta hai.
  Mongo connection process ke saath ek baar banta hai aur warm instance par
  reuse hota hai.

  Client SSR fetches (client/src/lib/api.ts) same origin
  (x-forwarded-host + /api/v1) use karte hain — Vercel par wahi domain, local
  par localhost:3000 → Next rewrite → localhost:5000. Koi env var zaroori nahi.

--------------------------------------------------------------------------------
2. FILES JO IS DEPLOYMENT KE LIYE HAIN
--------------------------------------------------------------------------------
  vercel.json (root)            services + public rewrites (route table)
  server/index.mjs              service entrypoint (express preset detection +
                                compiled server boot; .mjs = ESM guarantee)
  server/scripts/
    write-dist-manifest.mjs     dist/package.json ({"type":"module"}) — lambda
                                ESM ke liye
  .vercelignore                 .env / dist / .next / node_modules upload se
                                bahar (Vercel yahan .gitignore APPLY NAHI karta)
  server/src/create-app.ts      Express app factory (pehle src/app.ts — naam
                                badla, warna galat entrypoint detect hota tha)
  server/src/index.ts           Asli server: listen + DB bootstrap; Vercel par
                                DB fail hone par process.exit nahi, DEGRADED
                                mode + retry (function zinda rehta hai)
  server/src/config/env.ts      saare secrets env se (zod validated)
  client/next.config.ts         local dev proxy rewrite; Vercel par skip
                                (VERCEL env set hone par) — API wahan service hai
  client/src/lib/api.ts         SSR base = request ka apna origin (self-reference)

  Root `package.json` sirf workspace coordinator hai (client + server). Vercel
  usi se npm workspaces install karta hai; alag-alag lockfile ki zaroorat nahi.

4. DEPLOY — STEP BY STEP (CLI se kiya gaya)
--------------------------------------------------------------------------------
  STEP 0 — CLI login (ek dafa)
      npx vercel login            # device flow: link par ja kar Approve
      npx vercel whoami

  STEP 1 — Project link (framework auto = services)
      npx vercel link --yes --project qiststore
    `vercel link` root vercel.json padh kar project banata hai aur framework
    khud `services` set karta hai — output mein "Detected services: web
    [Next.js], api [Express]" aata hai. Project Settings mein check:
      framework = services, root directory = repo root (client/ ya server/ NAHI)
    (Agar aap dashboard se kar rahe hain to Framework Preset "Services"
    zaroori hai, warna `services` block IGNORE ho jayega.)

  STEP 2 — Environment Variables (ek command se)
      node scripts/push-vercel-env.mjs --dry     # kaunse keys jayenge (no values)
      node scripts/push-vercel-env.mjs           # server/.env se push (values
                                                 # kabhi terminal par print nahi
                                                 # hoti), target = prod+preview
      MONGO_URI              Atlas srV connection string
      JWT_ACCESS_SECRET      >= 8 chars random (local .env se alag)
      JWT_REFRESH_SECRET     >= 8 chars random, access se different
      CORS_ORIGIN            https://<your-domain>.vercel.app
      CLOUDINARY_CLOUD_NAME  image uploads (optional — nahi to upload 503)
      CLOUDINARY_API_KEY
      CLOUDINARY_API_SECRET
      NEXT_PUBLIC_SITE_URL   https://<your-domain>.vercel.app (sitemap/canonical)
                             ⚠️ yeh BUILD time par inline hota hai — pehli deploy se
                             pehle set karein; baad mein badalne par redeploy zaroori.
      (NEXT_PUBLIC_API_URL set NA karein — same-origin use hota hai)

  STEP 3 — Deploy
    npx vercel                     # preview (pehle isi par test karein)
    npx vercel --prod              # production → alias https://qiststore.vercel.app
    Build logs: npx vercel inspect <deployment-url> --logs
    Runtime logs: npx vercel logs --deployment <deployment-url>
    (CLI 47.0.5+ chahiye Express service ke liye; yahan 64.5.0 chala)

  STEP 3b — Deployment Protection OFF (public storefront ke liye)
    Naya project by default "Vercel Authentication" ke saath aata hai
    (ssoProtection = all_except_custom_domains) — public site par har visit
    login maangti hai. Ek dafa OFF karein:
      Vercel → Project → Settings → Deployment Protection → Vercel
      Authentication → Disabled
    (ya REST API: PATCH /v9/projects/<id> { "ssoProtection": null } — yehi
     kiya gaya, phir live URL publicly 200 deta hai.)

  STEP 4 — Atlas access
    MongoDB Atlas → Network Access → Vercel ke IPs allow karein
    (serverless IPs dynamic hote hain: 0.0.0.0/0 + strong DB password,
    ya Atlas pe private endpoint). Warna API 503 DB_UNAVAILABLE degi.

  STEP 5 — Data (ek baar, local machine se, Atlas DB par)
      npm run seed -w server            # categories/brands/content/admin
      npm run import:curated -w server  # catalogue (agar fresh DB hai)
    CLI scripts Vercel par nahi chalti — local se hi chalayen, DB wahi Atlas.

7. TROUBLESHOOTING
--------------------------------------------------------------------------------
  "Services build nahi hua / purana behaviour"
    → Framework Preset = Services + vercel.json mein `services` key, dono
      zaroori hain. Settings change ke baad REDEPLOY karein.
  Site 404 ya blank, API theek
    → web service ka root `client/` hai? Rewrite order mein catch-all last hai?
  /api/v1/* 404 (Next ka HTML 404)
    → api rewrite missing/misordered, ya framework Services par nahi.
  /health 200 lekin API 503 DB_UNAVAILABLE
    → MONGO_URI / Atlas Network Access / IP allowlist. Logs (Vercel → Logs)
      mein "MongoDB connected (verified)" line dhoondein.
  Login ke baad 401 (refresh)
    → CORS_ORIGIN exact domain (https, no trailing slash) + cookies same-origin
      honi chahiye; domain change par CORS_ORIGIN update karein.
  Admin image upload fail
    → Cloudinary env vars; Vercel ka request body limit ~4.5 MB hai
      (app ki 5 MB limit se chhota) — bade images direct Cloudinary par
      upload karein.
  Sitemap/canonical mein localhost
    → NEXT_PUBLIC_SITE_URL set karein, phir redeploy.
  Build fail: "TypeError: Cannot read properties of undefined (reading 'readFile')"
  (api service, message "Using TypeScript 7.0.2 (local user-provided)")
    → Vercel ke Express builder ka typecheck TypeScript 7 ke saath crash karta
      hai. Fix: server workspace mein TypeScript 5.9 pin karein
      (`npm i -w server -D typescript@5.9.3`). Client Next build TS 7 par
      theek chalta hai, is liye wahan change ki zaroorat nahi.
  Build pass, lekin har API route 500 / FUNCTION_INVOCATION_FAILED aur log mein
  "SyntaxError: Cannot use import statement outside a module /var/task/*.js"
    → lambda ko ESM chahiye tha. Do cheezein zaroori hain: (1) service
      entrypoint `.mjs` ho (server/index.mjs) aur (2) build `dist/package.json`
      mein {"type":"module"} likhe — `server/scripts/write-dist-manifest.mjs`.
  API 500 aur log mein entrypoint `app.ts` ho raha ho
    → `server/src/app.ts` ka naam aisa na rakhein jo Vercel entry detection
      pakad le (app/index/server/main). Renamed to `src/create-app.ts`.
  Deployment mein .env upload ho gaya
    → .vercelignore add karein; Vercel CLI .gitignore ko deploy par APPLY NAHI
      karta (log mein "Uploading 7.7MB" se pata chalta hai). Verify:
      REST API /v6/deployments/<id>/files → koi `.env` file nahi honi chahiye.
  Build logs: Vercel → Deployments → (deployment) → Build Logs (per service).
  Runtime logs: Vercel → Logs (service = api), pino JSON lines.

--------------------------------------------------------------------------------
8. LIMITS / NOTES
--------------------------------------------------------------------------------
  • Services abhi BETA hain, lekin saare plans par available hain. Billing
    Vercel Functions jaisi (Active CPU + invocations); Fluid compute default.
  • Express service timeout: plan ka default max duration (Hobby 10s, Pro 15s
    tak default; Fluid par max 300s). Mongo handshake normally 1–2s — agar
    Atlas slow ho to function timeout ho sakta hai → Atlas region ko Vercel
    region ke qareeb rakhein.
  • Upload body limit ~4.5 MB (upar dekhein).
  • `npm run seed` / `import:*` / `sync:images` / `check:*` scripts local CLI
    tools hain (Vercel par nahi chalti).
  • Cron/background jobs is setup mein nahi hain (Vercel Cron se alag function
    service add kar sakte hain).
  • Local dev same rahega: `npm run dev` (API :5000, web :3000, Next rewrite
    proxy karta hai). `npx vercel dev -L` se services ko locally bhi chala
    sakte hain (bin a login).

--------------------------------------------------------------------------------
9. FALLBACK (agar aapke plan/account par Services enable na ho)
--------------------------------------------------------------------------------
  Do alag projects (monorepo support built-in hai):
    client → Vercel (Root Directory: client, Framework: Next.js)
             env: NEXT_PUBLIC_API_URL=https://<api-host>/api/v1
    server → Render / Railway / Fly.io (npm run build -w server && npm start)
             env: MONGO_URI, JWT_*, CORS_ORIGIN=https://<web-domain>
  Code change nahi chahiye — api.ts pehle se NEXT_PUBLIC_API_URL respect karta
  hai. Is case mein root vercel.json use nahi hoga.
