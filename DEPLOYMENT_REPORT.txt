6. REQUEST FLOW + CORS (kaise wire kiya)
--------------------------------------------------------------------------------
  Browser:
      GET/POST https://qiststore-web.vercel.app/api/v1/...
        ↓ (same-origin — koi preflight nahi, cookie bhi same-site)
      Next.js rewrite (client/next.config.ts):
        source      /api/v1/:path*
        destination ${API_PROXY_URL}/api/v1/:path*   → qiststore-api
        ↓
      Express  /api/v1/*   (mongo/mongoose)

  SSR (client/src/lib/api.ts):
      NEXT_PUBLIC_API_URL set hai → server-to-server direct API call
      (CORS is path par lagu nahi hota).

  CORS (server side, create-app.ts):
      cors({ origin: env.CORS_ORIGIN.split(','), credentials: true })
      CORS_ORIGIN = https://qiststore-web.vercel.app
      → sirf usi origin ko allow karta hai, koi bhi doosra browser origin block.

  Auth cookies:
      qb_rt — HttpOnly, Secure, SameSite=Lax, Path=/api/v1/auth
      Same-origin proxy hone ki wajah se set/read dono theek chalte hain
      (cross-site cookie ki problem nahi aati).

9. ISSUES FOUND & FIXED (deployment ke doran)
--------------------------------------------------------------------------------
  1) `vercel link` ne subfolder se chalne par bhi repo ROOT ko project root
     maan liya → naya project framework=services ban gaya.
     FIX: REST API se framework=express + rootDirectory=server set kiya; root
          link wapas combined project par; subfolder .vercel links hata diye.

  2) API par pehli requests 503 DB_UNAVAILABLE / /health "degraded" de rahi
     thin (uptime seconds mein, ya idle-resume ke baad).
     Wajah: Vercel process ko Mongo handshake se pehle listen karwa deta hai,
            aur idle (frozen) instance resume hone par socket dead hoti hai.
     FIX (server code):
       • config/db.ts: connectDbOnce() + waitForDb() — initial handshake ka
         intezar (bounded), wake par bounded reconnect, readyState 2 ho to
         driver ka reconnect poll karna.
       • create-app.ts: request-level waitForDb() middleware (max 1.5s) aur
         /health par 3s tak settled state.
       • mongoose pool serverless-friendly: maxPoolSize=10, minPoolSize=0,
         maxIdleTimeMS=30s.
     RESULT: 15/15 health hits ok, 3 full verify runs clean.

  3) Build warning "The vercel.json file should be inside of the provided root
     directory." — ERROR nahi; matlab root ka services config in standalone
     projects par apply nahi ho raha (jo desired hai). Ignore karein.

12. LIMITATIONS / NOTES
--------------------------------------------------------------------------------
  • Vercel serverless body limit ~4.5 MB (app ki 5 MB image limit se chhota).
  • Serverless cold start ~1–3 s (Fluid compute; Mongo handshake ke saath).
    waitForDb() is window ko gracefully handle karta hai.
  • MongoDB Atlas par connections serverless instances ke saath share hote hain;
    pool 10/instance rakha gaya hai. Traffic barhe to Atlas connection limit
    (M0: 500) dekhna hoga.
  • API aur web alag domains par hain: `/health` sirf API domain par hai.
  • NEXT_PUBLIC_* / API_PROXY_URL build-time inline → change par rebuild.
  • Purana combined project `qiststore` (https://qiststore.vercel.app) abhi
    bhi live hai; dono setups ek hi Atlas DB use karte hain.
  • Seed/migration scripts Vercel par nahi chalti — local se chalayein
    (`npm run seed -w server` etc.), DB wahi Atlas.
  • Deploy ke waqt Vercel ne pehli deployment ko automatically production
    assign kiya (CLI ka standard behaviour pehli baar).
